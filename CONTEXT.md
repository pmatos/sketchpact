# Context

Domain terms used in Sketchpact's code and docs.

- **Board**: the shared Excalidraw scene the human and the agents edit. In code, the `Board` module (`src/server/board.ts`) is the only writer of agent edits: it owns the mutex, the layout mode decision, the version-checked commit and the readability gate. The canvas server's HTTP handlers are adapters over it.
- **Canvas session**: the MCP session's lazy readiness workflow in `src/mcp/canvas.ts`. `createCanvasSession(root, identity?).ready()` finds a healthy canvas daemon and registers the configured agent before returning its target and agent id together. Concurrent calls share registration for the same daemon URL and PID; a failed registration may be retried on the next call, and a replacement daemon requires registration again. Human-only sessions do not register.
- **Layout mode**: how a batch of edits is placed. `auto` re-lays-out the whole board (nobody has rearranged it), `kept` places new shapes incrementally and never moves the user's (they rearranged something), `forced` re-lays-out everything because the batch contained a `layout` op.
- **Arranged by the user**: the board's shape positions differ from the ones recorded after the last layout (`LayoutState`). This is the single signal behind both the layout mode and the readability gate's message.
- **Readability gate**: `yield_turn` is refused while the board has layout issues, unless they come from the user's own arrangement and the agent explicitly allows them.
- **Semantic scene**: nodes, edges, clusters and notes derived from raw Excalidraw elements. Agents only ever see this.
- **Semantic edit report**: the result of `applySemanticEdits` in `src/mcp/semanticEdits.ts`. It submits a batch to a ready canvas target and reports either indexed rejection messages or the semantic diff, current warnings, layout mode and server-reported layout problems. The before and after Semantic scenes are separate live reads around the edit, not a server snapshot transaction.
- **Label layout**: the shared wrapping, measurement and shape-fit policy in `src/shared/labels.ts`. `prepareLabel` preserves the unwrapped semantic text and produces display text plus required node dimensions; `labelFits` checks stored label dimensions for the readability gate, including human edits. Creation adds clearance beyond the shape's usable label area.
- **Arrow geometry**: the route representation and edge-label placement in `src/shared/labelpos.ts`. `readArrow` exposes absolute points, rendered label bounds and route intersections; `setArrowRoute` writes a route and its label together; `placeRoutedArrows` handles an ordered batch of collision-aware label placements. Incremental anchors and ELK route selection remain with their callers.
- **Scribe**: the first agent whose registration and owned frame successfully commit; the only one that may record the decision. A contended registration does not claim this role.
- **Decision recording**: the workflow in `src/mcp/decisions.ts` that checks the Scribe, agreement and required sections before capturing the live Board and writing its numbered Markdown record and Excalidraw diagram. `recordDecision` is the checked entry point; the MCP adapter starts the canvas and presents its result.
